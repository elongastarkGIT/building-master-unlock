MASTER UNLOCKER — Guide A à Z : Cloud Functions + Paiements
============================================================
Projet Firebase : master-unlock-db
Pour : propriétaire / admin technique (niveau Firestore + Auth)


0. CE QUE VOUS DEVEZ COMPRENDRE EN 2 MINUTES
--------------------------------------------

Aujourd'hui vous avez :
  - Frontend (HTML/JS) → lit/écrit Firestore + Auth
  - Checkout (pages/checkout.html) → UI prête, logique paiement VIDE
  - Dossier functions/ → N'EXISTE PAS encore dans le projet
  - js/payments/*.js → fichiers vides

Pourquoi Cloud Functions ?
  - Les clés secrètes CinetPay / Flutterwave / PayPal ne doivent JAMAIS être dans le frontend
  - La validation du paiement doit se faire côté serveur (webhook)
  - La création de commande (order) après paiement = logique métier serveur

Schéma du flux cible :

  Client remplit service → orderDraft (Firestore)
       ↓
  Client clique "Payer" → Cloud Function initPayment
       ↓
  Redirection vers CinetPay / Flutterwave / PayPal
       ↓
  Fournisseur confirme → Webhook → Cloud Function paymentWebhook
       ↓
  Function met payments.status = success + crée orders + notification

4. STRUCTURE FIRESTORE (RAPPEL — NE PAS INVENTER)
-------------------------------------------------

Collections utilisées par le paiement :

  orderDrafts/{draftId}
    - userId, serviceId, amount, currency, formData, status: "draft"

  payments/{paymentId}
    - userId, orderDraftId, amount, currency
    - provider: "cinetpay" | "flutterwave" | "paypal"
    - paymentMethod: "momo" | "card"
    - status: "pending" | "success" | "failed" | "cancelled"
    - providerTransactionId, createdAt

  orders/{orderId}
    - créé UNIQUEMENT après paiement success
    - status: "paid" puis "processing"
    - processingStatus: "waiting"

  notifications/{id}
    - type: "payment" ou "order"


5. CLOUD FUNCTIONS À CRÉER (4 FUNCTIONS MINIMUM)
------------------------------------------------

Fichier : functions/index.js

--- Function 1 : initPayment (HTTPS Callable) ---
  Appelée par le frontend quand l'utilisateur clique "Payer maintenant".
  Entrée : { orderDraftId, paymentMethod: "momo"|"card", provider: "cinetpay"|"flutterwave" }
  Actions :
    1. Vérifier que l'utilisateur est authentifié (context.auth.uid)
    2. Lire orderDraft dans Firestore, vérifier userId = uid
    3. Créer document payments/{id} avec status "pending"
    4. Appeler API CinetPay/Flutterwave avec la clé secrète (côté serveur)
    5. Retourner { paymentUrl } pour redirection client

--- Function 2 : paymentWebhook (HTTP Request) ---
  URL publique appelée par CinetPay/Flutterwave après paiement.
  Actions :
    1. Vérifier la signature / token du fournisseur (SÉCURITÉ CRITIQUE)
    2. Trouver le payment correspondant
    3. Si succès : payments.status = "success"
    4. Appeler la logique finalizePayment (Function 3 en interne)
    5. Répondre 200 OK au fournisseur

--- Function 3 : finalizePayment (interne, pas exposée) ---
  Actions :
    1. Lire orderDraft lié au payment
    2. Créer orders/{orderId} avec status "paid"
    3. Mettre orderDraft.status = "converted"
    4. Créer notification utilisateur
    5. (Optionnel) alerter admin

--- Function 4 : verifyPayment (HTTPS Callable) ---
  Appelée par le frontend au retour sur la page checkout (si webhook lent).
  Entrée : { paymentId }
  Actions :
    1. Vérifier auth
    2. Interroger l'API fournisseur OU lire payments.status
    3. Retourner { status, orderId }


6. SECRETS — OÙ METTRE LES CLÉS API
-----------------------------------

JAMAIS dans firebaseConfig.js ni dans le code frontend.

Méthode recommandée (Firebase Secret Manager) :

  firebase functions:secrets:set CINETPAY_API_KEY
  firebase functions:secrets:set CINETPAY_SITE_ID
  firebase functions:secrets:set FLUTTERWAVE_SECRET_KEY
  firebase functions:secrets:set FLUTTERWAVE_PUBLIC_KEY
  firebase functions:secrets:set PAYPAL_CLIENT_ID      (si PayPal)
  firebase functions:secrets:set PAYPAL_CLIENT_SECRET  (si PayPal)

Dans functions/index.js :
  const { defineSecret } = require("firebase-functions/params");
  const cinetpayKey = defineSecret("CINETPAY_API_KEY");

Puis attacher le secret à la function :
  exports.initPayment = onCall({ secrets: [cinetpayKey] }, async (request) => { ... });

  const db = admin.firestore();

8. CONFIGURER LES FOURNISSEURS DE PAIEMENT
------------------------------------------

--- A. CinetPay (MoMo + Carte — Afrique) ---
  1. Créer compte : https://cinetpay.com
  2. Récupérer : API Key + Site ID
  3. Dashboard CinetPay → URL de notification (webhook) :
     https://us-central1-master-unlock-db.cloudfunctions.net/paymentWebhookCinetpay
     (URL exacte après 1er déploiement — voir console Functions)
  4. URL de retour client :
     https://VOTRE-DOMAINE/pages/checkout.html?paymentId=XXX

--- B. Flutterwave (MoMo + Carte) ---
  1. Créer compte : https://flutterwave.com
  2. Récupérer : Public Key + Secret Key
  3. Dashboard → Webhooks :
     https://us-central1-master-unlock-db.cloudfunctions.net/paymentWebhookFlutterwave
  4. Activer les devises : USD, CDF selon votre marché

--- C. PayPal (optionnel) ---
  Le projet PRD prévoit CinetPay + Flutterwave. PayPal est possible en plus :
  1. Compte PayPal Business + Developer : https://developer.paypal.com
  2. Créer une App → Client ID + Secret
  3. Webhook PayPal → paymentWebhookPaypal
  4. Ajouter provider "paypal" dans payments.provider (extension future)

Recommandation MASTER UNLOCKER :
  - MoMo RDC / Afrique → CinetPay en priorité
  - Cartes internationales → Flutterwave
  - PayPal → seulement si clients internationaux le demandent

    → logique UI MoMo (numéro téléphone)

  js/orders/createOrder.js + orderDrafts.js
    → création orderDraft AVANT paiement

    → wrapper httpsCallable("initPayment"), etc.

Exemple appel frontend :
  import { httpsCallable, functions } from "../../firebase/firebaseConfig.js";
  const initPaymentFn = httpsCallable(functions, "initPayment");
  const result = await initPaymentFn({ orderDraftId, paymentMethod: "momo", provider: "cinetpay" });
  window.location.href = result.data.paymentUrl;


10. RÈGLES FIRESTORE (SÉCURITÉ PAIEMENTS)
-----------------------------------------

Créer firestore.rules à la racine si absent.

Principes :
  - Client peut CRÉER orderDraft (son userId)
  - Client peut LIRE ses propres payments/orders
  - Client NE PEUT PAS écrire payments.status = "success" (interdit)
  - Seul Admin SDK (Cloud Functions) peut valider un paiement

Exemple simplifié payments :
  match /payments/{paymentId} {
    allow read: if request.auth != null && resource.data.userId == request.auth.uid;
    allow create: if false;  // création via Function uniquement
    allow update: if false;   // mise à jour via Function uniquement
  }
