2) PRIORITÉ STRATÉGIQUE FOURNISSEURS (RDC + MONDE)
---------------------------------------------------

Décision recommandée (ordre de mise en prod) :

  Phase 1 (obligatoire) :
    - CinetPay pour MoMo RDC/Afrique + carte
    - Flutterwave pour cartes internationales

  Phase 2 (global) :
    - Stripe (si pays du compte le permet) OU garder Flutterwave pour cartes globales
    - PayPal en option (clients USA/EU habitués PayPal)

  Phase 3 (crypto) :
    - Coinbase Commerce ou Binance Pay (custodial simple)
    - Plus tard : paiements on-chain directs si besoin avancé

  Phase 4 (B2B crypto) :
    - Facture + wallet par entreprise + validation manuelle/automatique
    - KYC/AML partenaire avant activation gros volumes


3) ARCHITECTURE CIBLE (SÉCURITÉ)
--------------------------------

Toujours :
  Frontend -> Cloud Function -> Provider -> Webhook -> Firestore

Jamais :
  Frontend -> API provider secrète (interdit)

Flux standard :
  orderDraft (client) ->
  initPayment (function callable) ->
  payment URL provider ->
  webhook provider ->
  finalizePayment (serveur) ->
  create order + notification


4) CLOUD FUNCTIONS À CRÉER EN PREMIER
-------------------------------------

Minimum production :

  1. initPayment
     - Vérifie auth
     - Vérifie orderDraft et ownership
     - Crée payments/{id} status=pending
     - Retourne paymentUrl

  2. paymentWebhookCinetpay
     - Vérifie signature
     - Met payment success/failed
     - Lance finalizePayment

  3. paymentWebhookFlutterwave
     - Même logique que ci-dessus

  4. verifyPayment
     - Vérifie statut après retour client
     - Retourne status + orderId

  5. finalizePayment (interne)
     - Idempotent (ne jamais créer 2 orders)
     - Crée order depuis orderDraft
     - Met orderDraft converti

  6. initCryptoPayment (phase 3)
     - Crée invoice crypto chez provider
     - Retourne checkout URL / adresse / network

  7. paymentWebhookCrypto (phase 3)
     - Vérifie signature webhook crypto
     - Valide confirmations blockchain
     - Finalize order


5) ADAPTATION DES FICHIERS VIDES (SANS TOUCHER LE RESTE)
--------------------------------------------------------

  - js/payments/initPayment.js
      Appel httpsCallable("initPayment")

  - js/payments/verifyPayment.js

  - js/payments/momo.js

      Mapping opérateur si nécessaire

  - js/orders/orderDrafts.js
      Création/lecture orderDraft avant paiement
      Vérification montant/service côté serveur à la fin

  - firebase/functions.js
      Wrapper central des callables :
        initPayment, verifyPayment, initCryptoPayment

8) RISQUES ET MITIGATION (IMPORTANT)
------------------------------------

Risque: double commande
  Mitigation: finalizePayment idempotent + transaction Firestore

Risque: faux webhook
  Mitigation: vérification signature obligatoire + IP allowlist si possible

Risque: mismatch montant
  Mitigation: montant recalculé côté serveur depuis service/orderDraft

Risque: fraude carte/crypto
  Mitigation: seuil review manuelle + scoring + blacklist

Risque: indisponibilité provider
  Mitigation: fallback provider + statut retry + monitoring
